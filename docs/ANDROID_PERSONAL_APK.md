# AI Trade Pro — personal Android APK (paper-only)

This is a **sideloaded debug APK** for a personally owned Android device. It is not a Google Play Store release, and it does not enable production orders. The existing GitHub Pages web app and Render backend are not modified by building this APK.

## Build through GitHub Actions

1. Open the GitHub Actions workflow **Build Personal Android APK (Paper Only)**. A pull request containing the workflow also launches it automatically.
2. Open the **android-debug-apk** job and wait until it completes successfully.
3. Under **Artifacts**, download `AI-Trade-Pro-Personal-Paper-APK`.
4. Unzip the downloaded artifact on your phone or computer; it contains `app-debug.apk`.
5. Transfer the APK to your Android phone and install it after explicitly allowing installation from the file manager or browser you used. Disable that unknown-app permission again afterward.

A debug APK is signed with a development/debug key generated by the CI environment. It can be installed for testing, but future builds may use a different signing key, requiring uninstalling the older debug APK before installing a new one; uninstalling can erase browser-local journal/cache. A production-signed APK with a stable private signing key can be configured later if desired.

## Safety and data

- Existing platform protection applies: `PAPER_ONLY=true`, `REAL_ORDER_PLACED=false`, and `PRODUCTION_REAL_TRADING_ENABLED=false`.
- Backend: `https://ai-trade-pro-oauth.onrender.com`.
- Broker market-data credentials must remain **server-side**, never in the APK, GitHub, or browser-local storage.
- The frontend is bundled into the APK using Vite's relative `./` base path; `capacitor.config.json` declares `dist` as the web asset directory.
- The APK does **not** run a reliable continuous background market-data refresh. Refreshing the interface while open does not mean the app continues polling while the phone is locked. Server-based monitoring and Android push notifications require a separate backend feature.
- Opening Upstox login through the system browser and returning to the app requires on-device testing. The OAuth token remains server-side, and the normal broker session expiry/re-authentication rules continue to apply.
- An Android package is **not** proof that CE/PE trades are validated: if signal/contract/premium/risk checks fail, the correct output remains **WAIT**.
- This repository is public. GitHub Actions artifacts from public repositories should **not** be considered a confidential distribution method. Do not embed personal information or credentials, and use a private repository/artifact channel if restricted APK access is required.

## Reproduce locally (Node 22+, Android SDK, Java 21)

```bash
npm ci
npm install --no-save --package-lock=false @capacitor/core@8.0.0 @capacitor/android@8.0.0 @capacitor/cli@8.0.0
VITE_UPSTOX_READONLY_API_BASE=https://ai-trade-pro-oauth.onrender.com npm run build -- --base ./
npx cap add android
npx cap sync android
cd android
./gradlew assembleDebug
```

The resulting file is `android/app/build/outputs/apk/debug/app-debug.apk`.

## Validation checklist

1. Android launch and screen layout/navigation.
2. Backend `/health` and `/api/upstox/status` reachability over HTTPS.
3. System-browser Upstox sign-in and session refresh (no browser-exposed tokens).
4. Completed 09:15–09:30 index candles, following completed 5-minute candles, and 30-second quote updates.
5. CE/PE/WAIT analysis, expiry/contract checks, 5-minute frozen predictions, and later outcome journal.
6. Confirm no live order submission or trade placement is available.
